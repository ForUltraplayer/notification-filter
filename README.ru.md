# Push Filter

**Фильтрация уведомлений по регулярным выражениям для Android.** Заглушить рекламу от приложения,
не заглушая само приложение.

## Зачем это нужно

Доставка пишет, что курьер у подъезда. И тут же — про скидку 20% на роллы. Банк подтверждает
списание, а следом предлагает кредитку. Android умеет только выключить у приложения **все**
уведомления или оставить **все**.

Push Filter встаёт между приложением и шторкой и решает по каждому уведомлению отдельно — по
регулярным выражениям, которые пишете вы.

## Возможности

- **Два режима.** Блокировать совпадения или пропускать **только** совпадения. Оба режима можно
  смешивать на одном приложении.
- **Правила для приложения или для всех сразу.**
- **Ищет по всему уведомлению.** Заголовок, текст, развёрнутый текст, списки строк и переписки
  в стиле мессенджера — реклама часто прячется именно в тех полях, которых не видно в свёрнутом
  виде.
- **Живой тестер регулярок.** Вставьте настоящее уведомление прямо в редактор и увидите вердикт
  до сохранения правила.
- **Журнал уведомлений.** Всё, что пришло, — и заблокированное, и пропущенное, с поиском и
  фильтрами. Любая запись одним нажатием превращается в правило с подставленным приложением и
  текстом.
- **Список игнорируемых приложений.** Пропускаются раньше всех проверок: не фильтруются и в
  журнал не попадают.
- **Резервная копия.** Экспорт и импорт правил, списка игнора и всех настроек в читаемый JSON.
- **Срок хранения журнала.** 1, 7, 30 дней или бессрочно; старые записи удаляются сами.
- **Приватность по устройству программы.** Нет разрешения на интернет, нет аналитики, нет
  аккаунтов. Текст уведомлений не покидает телефон.
- **Интерфейс Material 3** на русском и английском, с динамическими цветами на Android 12+.

## Установка

### Скачать готовое

Возьмите подписанный APK со [страницы релизов](https://github.com/Rai220/push-filter/releases/latest)
и откройте на телефоне. Понадобится разрешить установку из браузера или проводника.

Через кабель:

```bash
adb install push-filter-1.3.apk
```

### Первый запуск

Нужен **доступ к уведомлениям** — разрешение, позволяющее читать и убирать уведомления. Выдать
его изнутри приложения нельзя, поэтому Push Filter покажет плашку, которая ведёт на нужный экран
системных настроек. Найдите там *Push Filter* и включите.

Пока не добавлено ни одного правила, ничего не фильтруется. Дайте приложению полчаса обычного
пользования и откройте вкладку **Журнал**: там будут настоящие тексты всего пришедшего — именно
по ним и удобно писать выражения.

## Как принимается решение

По каждому пришедшему уведомлению, по порядку:

1. **Приложение в списке игнорируемых?** → не трогаем, в журнал не пишем.
2. **Фильтрация выключена?** → не трогаем.
3. **Это постоянное уведомление или сводка группы?** → пропускаем, если включены эти настройки.
4. **Совпало хоть одно включённое блокирующее правило?** → **блокируем.** Блокирующее правило —
   это вето.
5. **Совпало хоть одно включённое разрешающее правило?** → **пропускаем.**
6. **У приложения есть разрешающие правила, но ни одно не совпало?** → **блокируем.** Одно
   разрешающее правило превращает приложение в белый список.
7. **Иначе** → пропускаем.

Правила с целью *Все приложения* участвуют в шагах 4–6 для любого приложения.

Именно этот порядок позволяет двум режимам уживаться. Можно оставить у банка только уведомления
о списаниях и параллельно глушить одну рекламную фразу во всех приложениях телефона.

## Как писать правила

Выражения — обычные регулярки: `|`, `^`, `$`, `\d`, `{2,4}` работают как везде. Поиск идёт
**по подстроке**, поэтому `скидк` совпадает с `Большие скидки сегодня` — обрамлять выражение `.*`
не нужно. Регистр по умолчанию не учитывается (это переключается), а `^` и `$` привязываются к
строке, а не ко всему тексту. Рядом с полем в редакторе лежит несколько разобранных примеров.

| Задача | Выражение | Режим |
| --- | --- | --- |
| Убрать типовую рекламу | `скидк\|акци\|распродаж\|промокод` | Блокировать |
| Убрать англоязычную рекламу | `sale\|discount\|promo\|% off` | Блокировать |
| Убрать всё с рекламной пометкой в начале | `^Реклама: ` | Блокировать |
| Оставить только уведомления о деньгах | `списан\|поступлен\|баланс` | Только совпадения |
| Оставить сообщения одного человека | `^Анна: ` | Только совпадения |
| Убрать надоевшую просьбу | `Оцените приложение` | Блокировать |

Две вещи, которые сильно экономят время:

- В редакторе есть **Искать в**: можно сузить поиск только до заголовка или только до текста.
  Полезно, когда приложение кладёт отправителя в заголовок.
- В журнале есть **Создать правило из этого**: подставляется приложение, а текст уведомления
  экранируется в literal-выражение. От него удобно отталкиваться и расширять.

## Формат резервной копии

Экспорт даёт читаемый JSON — правила, список игнорируемых приложений и все настройки. Копию можно
править руками и передавать другим:

```json
{
  "format": 2,
  "exportedAt": 1753795200000,
  "rules": [
    {
      "package": "com.example.shop",
      "name": "Реклама",
      "mode": "BLOCK",
      "pattern": "скидк|акци|распродаж",
      "target": "BOTH",
      "caseSensitive": false,
      "enabled": true
    }
  ],
  "ignoredApps": ["org.telegram.messenger"],
  "settings": {
    "filteringEnabled": true,
    "logAllowed": true,
    "ignoreOngoing": true,
    "ignoreGroupSummary": true,
    "retentionDays": 7
  }
}
```

`mode` — это `BLOCK` или `ALLOW`, `target` — `TITLE`, `TEXT` или `BOTH`, а в `package` можно
поставить `*`, чтобы правило действовало везде. Любое поле `settings` можно не писать — возьмётся
значение по умолчанию, а файл вообще без этого блока (всё, что выгружено до формата 2) импортируется
как раньше и настройки на телефоне не трогает.

При импорте спрашивается, заменить всё или добавить к имеющемуся. *Заменить* восстанавливает и
настройки, *Добавить* приносит только правила и список игнора: осмысленно слить два переключателя
всё равно нельзя.

## Сборка из исходников

Нужны **JDK 17** и Android SDK (compile SDK 36). Android Studio не обязателен.

```bash
git clone https://github.com/Rai220/push-filter.git
cd push-filter
./gradlew assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

Те же проверки, что гоняет CI:

```bash
./gradlew testDebugUnitTest lintDebug
```

`assembleRelease` работает без всякой настройки: если ключа подписи в окружении нет, релизная
сборка подписывается debug-ключом, так что результат всё равно можно установить.

### Подпись своим ключом

Релизная сборка читает ключ из четырёх переменных окружения. Ничего не читается из файлов внутри
репозитория.

```bash
export PUSHFILTER_KEYSTORE=/путь/к/release.jks
export PUSHFILTER_KEYSTORE_PASSWORD=...
export PUSHFILTER_KEY_ALIAS=...
export PUSHFILTER_KEY_PASSWORD=...
./gradlew assembleRelease
```

Чтобы публиковать релизы из форка, добавьте секреты репозитория и запушьте тег `v*`:

| Секрет | Содержимое |
| --- | --- |
| `KEYSTORE_BASE64` | Файл keystore в base64 (`base64 -i release.jks`) |
| `KEYSTORE_PASSWORD` | Пароль хранилища |
| `KEY_ALIAS` | Псевдоним ключа |
| `KEY_PASSWORD` | Пароль ключа |

Релизный workflow отказывается публиковать сборку, если секрета с ключом нет, проверяет подпись
готового APK и удаляет расшифрованный keystore с раннера после сборки.

## Как это устроено

[`NotificationListenerService`](app/src/main/java/ru/krestnikov/pushfilter/filter/NotificationFilterService.kt)
получает каждое показанное уведомление, вытаскивает из него текст, спрашивает вердикт у движка
фильтрации и вызывает `cancelNotification()`, если вердикт — «заблокировать».

```
app/src/main/java/ru/krestnikov/pushfilter/
├── data/          Хранение в SQLite: правила, журнал, настройки, JSON-бэкап
├── filter/        Извлечение текста, кэш регулярок, FilterEngine, служба-слушатель
├── apps/          Названия и иконки установленных приложений
└── ui/            Экраны на Compose: правила, редактор, журнал, настройки
```

Заметки по устройству:

- **Правила лежат в памяти.** Вердикт считается в главном потоке через микросекунды после показа
  уведомления, ждать диск нельзя. Источник истины — SQLite, а слушатель читает снимок
  `StateFlow`.
- **Скомпилированные выражения кэшируются.** Компилировать `Regex` на каждое уведомление
  расточительно; сломанные выражения кэшируются как неудача, чтобы битое правило тоже было
  дешёвым.
- **Журнал дедуплицируется.** Приложения переотправляют одно и то же уведомление при каждом
  обновлении прогресса, поэтому повторы с одинаковым содержимым в пределах 5 секунд не пишутся.
- **Без Room и KSP.** Две таблицы не оправдывают процессор аннотаций и его матрицу совместимости,
  поэтому хранилище — обычный `SQLiteOpenHelper` с включённым WAL.

Логика фильтрации покрыта юнит-тестами:
[`FilterEngineTest`](app/src/test/java/ru/krestnikov/pushfilter/filter/FilterEngineTest.kt).

## Требования

- Android 8.0 (API 26) или новее
- Выданный приложению доступ к уведомлениям

## Известные ограничения

Всё это идёт от самого Android и приложением не лечится:

- **Заблокированное уведомление может мелькнуть.** Службы-слушатели узнают об уведомлении
  **после** его показа, поэтому удаление происходит на миллисекунды позже.
- **Звук и вибрацию задаёт приложение-отправитель**, подавить их до удаления удаётся не всегда.
  Если мешает — поставьте каналу этого приложения беззвучный режим.
- **Агрессивная экономия батареи** на Xiaomi, Huawei, Samsung и других может выгружать службу
  после перезагрузки. Если фильтрация замолчала — разрешите приложению работать в фоне.
- **Сопоставляется текст уведомления.** Содержимое, которое существует только внутри
  собственной разметки `RemoteViews`, прочитать нельзя.

## Приватность

Приложение не запрашивает разрешение на интернет. Правила, журнал и настройки лежат в приватном
хранилище приложения, исключены из облачного бэкапа и переноса на другое устройство и попадают в
файл только тогда, когда вы сами нажимаете «Экспорт».

`QUERY_ALL_PACKAGES` объявлено ровно по одной причине: редактор правил показывает список
установленных приложений, чтобы можно было выбрать нужное.
